KEV 10건 신규 — WordPress·F5·WSO2 인증 없이 장악, Check Point 지난 호 1건 악용 확인으로 변경.
개인 정리 자료 · 비공식
KISA 보호나라 보안공지 주간 리포트
대상 기간: 2026.09.21(월) ~ 09.27(일)  |  발행: 2026.09.28(월)

본 페이지는 공개된 원문을 바탕으로 작성한 개인 정리 자료이며, 한국인터넷진흥원(KISA)의 공식 발행물이 아닙니다. 관련 원문은 보호나라 보안공지 등 공식 출처에서 확인할 수 있습니다.

1. 한눈에 보기

대상 기간에 보호나라 보안공지 4건(#2545~#2548)이 게시됐고, 같은 기간 CISA 악용 확인 목록(KEV)에 10건이 신규 등재됐습니다. 중복 2건을 제외하면 점검 대상은 12건이며, 이 중 2건은 지난 호 수록분이라 이번 호 신규는 10건입니다. 이번 주는 보호나라 공지보다 KEV 쪽이 훨씬 무겁습니다 — 신규 10건 중 8건이 KEV에서만 확인됐습니다.

인증 없이 시스템을 장악할 수 있는 건이 세 개 겹쳤습니다. WordPress(CVE-2026-87902, CVSS 9.2)는 4.7 이후 거의 모든 버전이 대상이고, F5 BIG-IP APM(CVE-2026-94127, CVSS 9.8)은 제로데이로 악용된 뒤 패치됐으며, WSO2 API Manager(CVE-2026-5430, CVSS 10.0)는 JWT 인증 우회로 관리자 계정까지 탈취됩니다. 세 건 모두 KEV 연방기관 기한이 이미 지났습니다.

지난 호 항목 하나의 상태가 바뀌었습니다.
지난 호 Check Point 6건 중 CVE-2026-85102(VPN 인증서 신뢰 검증 미흡)는 그때 ‘악용 미확인 · KEV 미등재’로 적었는데, 9/22 KEV에 등재되어 악용 확인으로 바뀌었습니다. Check Point 장비를 운영 중이라면 이 건의 우선순위를 올려 주십시오.

보호나라 공지 4건은 Linux 커널(#2545), WordPress 2건(#2546·#2547), Check Point(#2548)입니다. 이 중 Linux 커널 #2545는 지난 호에 이미 실은 3건(CVE-2025-39682 · CVE-2025-39964 · CVE-2026-53266)을 보호나라가 뒤늦게 게시한 것이어서, 내용을 반복하지 않고 조치 현황만 추적합니다.

네트워크·보안 장비 쪽 비중이 큽니다. F5, Check Point, Arista VeloCloud, MikroTik RouterOS, Zyxel 스위치까지 다섯 계열이 한 주에 몰렸습니다. 경계 구간 장비는 장악당하면 내부 전체가 노출되므로, 사용 여부 확인을 먼저 해 주시기 바랍니다.

3-1. WordPress — CVE-2026-87902

긴급 · CVSS 9.2 · 악용 확인  |  KISA #2547(9/23 게시) · KEV 등재 9/25(기한 9/28)
상황 페이지 템플릿을 찾는 get_page_template() 처리에 경로 조작이 가능해, 인증 없는 공격자가 활성 테마 디렉터리 밖의 임의의 읽기 가능한 .php 파일을 포함시킬 수 있습니다. 서버 구성과 테마 조건이 맞으면 원격 코드 실행으로 이어집니다(벤더 표현: conditional RCE).
CVSS 9.2 · CVSS:4.0/AV:N/AC:L/AT:P/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N (출처: WordPress 보안권고) · CWE-98
영향 범위가 이번 주에서 가장 넓습니다. 4.7.0부터 7.1.1까지 25개 브랜치가 모두 대상입니다. CISA는 9/25 KEV에 등재했고 연방기관 기한은 9/28입니다.
조치 사용 중인 브랜치의 수정 버전 이상으로 업데이트합니다. 벤더가 25개 브랜치 전부에 패치를 내놓았습니다.
4.7.37 · 4.8.32 · 4.9.33 · 5.0.29 · 5.1.26 · 5.2.28 · 5.3.25 · 5.4.23 · 5.5.22 · 5.6.21 · 5.7.19 · 5.8.17 · 5.9.18 · 6.0.16 · 6.1.14 · 6.2.13 · 6.3.12 · 6.4.12 · 6.5.12 · 6.6.9 · 6.7.9 · 6.8.10 · 6.9.9 · 7.0.6 · 7.1.2
벤더 권고에 우회책 기재가 없습니다.
※ 보호나라 #2547 표에서는 영향 범위 상한이 7.1.2로 취득됐으나, 벤더 권고는 영향 7.1.1까지·해결 7.1.2로 기재하고 있어 같은 값이 양쪽에 나타납니다. 위 버전은 벤더 공식 권고를 기준으로 적었습니다. 어느 쪽이 옳은지는 단정하지 않습니다.
조치 적용 확인 ① 관리자 화면 알림판 > 업데이트 또는 도구 > 사이트 건강 > 정보에서 WordPress 버전이 해당 브랜치의 수정 버전 이상인지 확인합니다.
② 자동 업데이트가 켜져 있어도 메이저 브랜치는 자동으로 올라가지 않을 수 있으므로 실제 버전 값을 직접 확인합니다.
③ 다중 사이트(멀티사이트)·다수 인스턴스는 사이트별로 각각 확인합니다.
④ [미확인] WP-CLI 등 명령행 확인 절차는 이번 조사에서 공식 문서로 확인하지 않아 싣지 않습니다.
침해 흔적 확인 벤더가 공식 확인 방법이나 침해 지표를 제공하지 않습니다. 확인 방법이 없다는 것이 침해가 없다는 뜻은 아닙니다. 확인되지 않은 지표를 만들어 싣지 않았습니다.
공격 원리에서 도출한 점검 착안점(벤더 IoC 아님) — 이 취약점은 활성 테마 밖의 .php 파일을 템플릿으로 포함시키는 방식입니다. 따라서 패치 전 기간의 웹 접근 로그에서 템플릿·페이지 파라미터에 경로 조작 문자열이 섞인 요청이 있었는지, 업로드 디렉터리 등에 등록한 적 없는 .php 파일이 생겼는지 확인합니다.

3-2. F5 BIG-IP APM — CVE-2026-94127

긴급 · CVSS 9.8 · 악용 확인  |  KEV 등재 9/22(기한 9/25) · 보호나라 공지 대상 아님
상황 BIG-IP APM의 힙 버퍼 오버플로로 인증 없는 원격 공격자가 코드를 실행할 수 있습니다. 제로데이로 악용된 뒤 패치됐습니다.
CVSS 9.8(v3.1).
중요 — 기본 구성에서는 노출되지 않습니다. 가상 서버에 APM 액세스 정책과 OAuth 프로필이 함께 구성된 경우에만 악용 가능합니다. 따라서 BIG-IP를 쓰더라도 OAuth를 쓰지 않으면 해당하지 않을 수 있으나, 구성 여부를 실제로 확인해야 판단할 수 있습니다.
조치 F5가 제공한 엔지니어링 핫픽스를 적용합니다.
· BIG-IP 21.1.0 → Hotfix-BIGIP-21.1.0.2.0.30.22-ENG
· BIG-IP 17.5.0 → Hotfix-BIGIP-17.5.1.9.0.160.12-ENG
· BIG-IP 17.1.0 → Hotfix-BIGIP-17.1.3.5.0.41.14-ENG
즉시 패치가 어려우면 F5 지원에서 iRule 기반 우회책을 제공합니다. 우회책은 패치를 대체하지 않습니다.
※ F5 공식 문서(K000162605)가 자동 조회로 열리지 않아, 위 값은 보안업체 분석 자료 기준입니다. 적용 전 F5 지원 문서를 직접 확인해 주십시오.
조치 적용 확인 ① 먼저 해당 여부부터 — 가상 서버 목록에서 APM 액세스 정책과 OAuth 프로필이 동시에 적용된 가상 서버가 있는지 확인합니다. 없으면 이 건은 해당하지 않습니다.
② 설치된 핫픽스 빌드가 위 값과 일치하는지 확인합니다.
③ 고가용성(HA) 구성이면 양쪽 장비 모두 확인합니다.
④ [미확인] 버전·핫픽스 확인용 정확한 명령이나 콘솔 경로를 공식 문서로 확인하지 못해 싣지 않습니다.
침해 흔적 확인 [미확인] — 공식 침해 지표를 확인하지 못했습니다. 확인 방법이 없다는 것이 침해가 없다는 뜻은 아닙니다.
제로데이로 악용된 건이므로, 해당 구성이 있었다면 패치 전 기간의 APM·OAuth 관련 로그와 장비발 외부 통신을 함께 확인하시기 바랍니다(벤더 IoC 아님).

3-3. WSO2 API Manager 외 — CVE-2026-5430

긴급 · CVSS 10.0 · 악용 확인  |  KEV 등재 9/24(기한 9/27) · 보호나라 공지 대상 아님
상황 벤더 설명 — “JWT authentication can be bypassed when a token is signed using an unsupported algorithm, allowing unauthorized access.” 지원하지 않는 알고리즘으로 서명한 토큰을 그대로 받아들여 인증이 우회됩니다. 벤더는 관리자 계정 탈취와 전체 계정 장악까지 가능하다고 적고 있습니다.
CVSS 10.0(단일 테넌트 환경 9.8), 인증 불필요(PR:N).
보안업체 허니팟에서 9/13부터 악용 시도가 관측됐고, CISA가 9/24 KEV에 등재했습니다. 공공·금융·통신 분야에서 널리 쓰이는 제품이라 납품·운영 시스템에 포함돼 있는지 확인이 필요합니다.
조치 영향 제품·버전 — API Manager 4.1.0 / 4.2.0 / 4.3.0 / 4.4.0 / 4.5.0 / 4.6.0, API Control Plane 4.5.0 / 4.6.0, Traffic Manager 4.5.0 / 4.6.0, Universal Gateway 4.5.0 / 4.6.0
· 지원 계약이 있는 환경 — WSO2 Updates로 지정 업데이트 레벨을 적용합니다. 제품·버전별로 요구 레벨이 다릅니다(Update 21 ~ 257 범위).
· 오픈소스 사용 환경 — 공개된 수정본을 적용하거나 영향받지 않는 버전으로 올립니다.
벤더 권고에 우회책 기재가 없습니다.
조치 적용 확인 ① 제품별 적용된 업데이트 레벨이 권고가 지정한 값 이상인지 확인합니다. 제품 버전만으로는 판별되지 않습니다.
② 게이트웨이·컨트롤 플레인 등 구성요소를 각각 확인합니다. 한 구성요소만 올리면 경로가 남습니다.
③ [미확인] 업데이트 레벨 확인용 정확한 명령·화면 경로는 공식 문서로 확인하지 못해 싣지 않습니다.
침해 흔적 확인 벤더가 공식 확인 방법이나 IoC를 제공하지 않습니다. 확인 방법이 없다는 것이 침해가 없다는 뜻은 아닙니다.
공격 원리에서 도출한 점검 착안점(벤더 IoC 아님) — 인증 우회가 성립하면 정상 발급 이력이 없는 토큰으로 성공한 인증이 남습니다. 패치 전 기간(특히 9/13 이후)의 인증 성공 로그에서 발급 이력과 대조되지 않는 접근, 관리자 권한 API 호출, 새로 생긴 계정·토큰을 확인하시기 바랍니다.

3-4. Check Point — CVE-2026-93616 · CVE-2026-85102

긴급 · 악용 확인  |  KISA #2548(9/23 게시) · KEV 등재 9/22(기한 9/25)

① CVE-2026-93616 — 신규 (KISA #2548 · KEV 9/22)

3-11. Linux 커널 3건 (지난 호 수록 · 조치 현황 추적)

악용 확인  |  KISA #2545(9/21 게시) · KEV 등재 9/18 · 기한 9/21 경과

보호나라 #2545(9/21)는 지난 호에 이미 실은 세 건(CVE-2025-39682 · CVE-2025-39964 · CVE-2026-53266)을 뒤늦게 게시한 것입니다. 신규 악용 정보 · 신규 IoC · 신규 완화책 · 해결 버전 변경 · 추가 영향 제품 — 모두 없습니다. 내용을 반복하지 않고 조치 현황만 추적합니다.

다만 보호나라 표가 브랜치별 해결 버전을 정리해 제공한 점은 참고할 만합니다 — CVE-2025-39682는 6.1.149 · 6.6.103 · 6.12.44 · 6.16.4 · 6.17, CVE-2025-39964는 5.10.245 · 5.15.194 · 6.1.154 · 6.6.108 · 6.12.49 · 6.16.9 · 6.17, CVE-2026-53266은 5.10.259 · 5.15.210 · 6.1.176 · 6.6.143 · 6.12.94 · 6.18.36 · 7.0.13 · 7.1 이상입니다.

지난 호에 적은 주의점은 그대로 유효합니다. 위 값은 업스트림(kernel.org) 기준이므로, 배포판 커널은 백포트가 적용되어 업스트림 버전 번호만으로 해당 여부를 판단할 수 없습니다. 배포판별 해결 커널 버전은 여전히 [미확인]이며, 각 배포판의 CVE 페이지를 확인해야 합니다.

아직 적용하지 않았다면 배포판 벤더가 제공하는 최신 커널로 업데이트한 뒤 재부팅하고, uname -r로 동작 중인 커널을 확인하십시오. KEV 연방기관 기한(9/21)은 이미 지났습니다.
