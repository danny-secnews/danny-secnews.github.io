1. 한눈에 보기

대상 기간에 보호나라 보안공지 7건(#2538~#2544)이 게시됐고, 같은 기간 CISA 악용 확인 목록(KEV)에 7건이 신규 등재됐습니다. 이 가운데 추석 관련 일반 주의 공지 2건은 특정 제품·버전을 지정하지 않아 제외했고, Cisco 2건은 두 수집원에 중복돼 한 건으로 묶었습니다. 결과적으로 이번 호 점검 대상은 9건이며 이 중 8건은 실제 악용이 확인됐습니다.

가장 급한 것은 Cisco 두 건입니다. Cisco ISE·ISE-PIC(CVE-2026-76460, CVSS 10.0)와 Cisco Secure Email Gateway(CVE-2026-76461, CVSS 9.8)는 모두 Cisco PSIRT가 실제 악용을 확인했고, 인증 없이 root 권한 명령 실행까지 이어집니다. KEV 기준 연방기관 조치 기한(9/19 · 9/17)은 이미 지났습니다.

리눅스 커널 3건 — KEV 조치 기한이 오늘(9/21)입니다.
CISA가 9/18 리눅스 커널 취약점 3건(CVE-2025-39682 · CVE-2025-39964 · CVE-2026-53266)을 KEV에 등재했습니다. 보호나라 공지 대상은 아니지만 악용이 확인된 건이고, 사내 리눅스 서버와 컨테이너 호스트가 모두 해당할 수 있습니다.

9/18에 올라온 공지 2건이 이번 호에 새로 들어왔습니다. #2543(Check Point 6건)과 #2544(Cisco 2건)입니다. Check Point 6건 중 CVE-2026-16232(SmartConsole 인증 우회)는 이미 7/22 KEV에 등재되고 공개 PoC가 나온 건으로, 7월 패치를 적용하지 않은 관리 서버는 두 달째 노출된 상태입니다.

침해 흔적 확인이 이번 주에 특히 중요합니다. Cisco 두 건의 벤더 권고는 공격자가 root 권한을 얻으면 로그와 침해 지표를 지우거나 숨길 수 있다고 명시하고, 장비 내부 로그만 보지 말고 네트워크·방화벽 등 외부 로그를 교차 확인하라고 권고합니다. 제시된 탐지 예시도 벤더가 스스로 non-exhaustive라고 적고 있어, 결과가 비어 있다고 해서 침해가 없다고 볼 수 없습니다.

지난 호 수록분 중 Fortinet(CVE-2025-25249)은 이번 주에 확인된 신규 사실만 정리했고, GitLab(CVE-2026-85706)은 신규 사실이 없어 조치 현황만 추적합니다.

3-1. Cisco Identity Services Engine · ISE-PIC — CVE-2026-76460

긴급 · CVSS 10.0 · 악용 확인  |  KISA #2544(9/18 게시) · KEV 등재 9/16
상황 API 엔드포인트의 인증 제어가 충분하지 않아, 인증 없는 원격 공격자가 조작한 요청 하나로 웹 기반 관리 인터페이스를 우회하고 장비에 접근할 수 있습니다. CVSS 10.0(AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H)으로, 구성과 무관하게 ISE와 ISE-PIC 전체가 영향을 받습니다.
Cisco PSIRT는 실제 악용을 확인했습니다 — “The Cisco PSIRT is aware of active exploitation of this vulnerability.” CISA는 9/16 KEV에 등재했고 연방기관 기한은 9/19로 이미 지났습니다. 악용에 성공하면 root 권한 명령 실행까지 이어질 수 있습니다.
벤더 권고 제목은 “Cisco Identity Services Engine Authentication Bypass Vulnerability”, KEV 등재명은 “Cisco Identity Services Engine Incorrect Use of Privileged APIs Vulnerability”로 표기가 다르지만 같은 CVE입니다.
조치 · 해결 패치 적용 — 3.1 Patch 12 / 3.2 Patch 11 / 3.3 Patch 12 / 3.4 Patch 7 / 3.5 Patch 4 (KISA #2544 표와 벤더 권고 일치)
· 3.0 계열은 지원 종료 — 벤더: “Cisco ISE Software Release 3.0 has reached End of Software Maintenance. Customers are advised to migrate to a supported release that includes the fix.”
· 우회책은 없습니다. 패치 전 완화책으로 벤더는 iACL 적용을 제시합니다 — 필요한 관리·제어 트래픽만 해당 장비로 허용. 완화책은 패치를 대체하지 않습니다.
조치 적용 확인 ① 설치 버전 — CLI show version(“Displays software version and installation information for the system”) 또는 GUI About ISE and Server. 설치된 패치 목록은 Open API의 Patch and Hot Patch(“listing all the installed patches”).
② 실행 상태 기준 확인 — [미확인] 조회한 공식 문서에서 패치 적용 뒤 실행 상태 기준 확인 방법을 찾지 못했습니다.
③ 재시작 필요 여부 — [미확인] 패치 설치 시 서비스 재시작 여부를 조회 문서에서 찾지 못했습니다.
④ 분산 배포 전 노드 — 적용·확인 절차는 [미확인]. 다만 침해 흔적 확인은 벤더가 전 노드 수행을 명시하고 있습니다(아래).
②③④는 공식 문서로 확인하지 못했습니다. 패치 적용 후 Cisco TAC 또는 배포 담당 파트너를 통해 확인 절차를 받아 보완해 주십시오.
침해 흔적 확인 아래는 모두 Cisco 권고 원문의 지시입니다.
· access.log에서 의심 사용자명을 확인합니다 — “To confirm any attempted exploitation of this vulnerability, review the access.log and look for suspicious usernames.”
· 분산 배포면 각 노드의 로그를 확인합니다 — “If the device is part of a distributed deployment, review the logs of each node.”
· 벤더가 제시한 탐지 예시(벤더 표기: non-exhaustive):
  admin#show logging application ise-kong/access.log | include dummyuser
· 추가 access.log는 support bundle을 include debug logs 선택 + shared key encryption으로 수집한 뒤 복호화해 ./ise/logs/apigateway/access.log..gz에서 확인합니다.
· “The presence of any entry in the output may indicate malicious activity. This should be done on every node in the deployment.”
· 악성 활동이 의심되면 — “it is strongly recommended to re-image the affected nodes and restore from configuration backup if needed.”
· root 권한 획득 시 — “evidence of exploitation and indicators of compromise may be removed or hidden by the threat actors.”
· 외부 로그 교차 확인 — “Cisco strongly recommends that administrators cross-check the network logs and the firewall logs outside of the impacted device…”

3-2. Cisco Secure Email Gateway (AsyncOS) — CVE-2026-76461

긴급 · CVSS 9.8 · 악용 확인  |  KISA #2544(9/18 게시) · KEV 등재 9/14
상황 메일 파싱 로직의 입력 검증이 불충분해, 조작한 메일을 보내는 것만으로 인증 없이 임의 SQL 문이 실행되고 하부 운영체제에서 root 권한 명령 실행까지 이어집니다(CVSS 9.8). 물리·가상 장비 모두, 구성과 무관하게 영향을 받습니다.
Cisco PSIRT — “In September 2026, the Cisco PSIRT became aware of active exploitation of this vulnerability.” KEV 9/14 등재, 연방기관 기한 9/17로 이미 지났습니다. 권고는 9/17 버전 1.1에서 클러스터 관련 설명이 추가됐습니다.
벤더가 영향 없음을 확인한 제품: Secure Email and Web Manager, Secure Web Appliance.
조치 · 트레인별 첫 수정 릴리스 이상으로 업그레이드 — 15.5 이하 → 15.5.5-014 / 16.0 → 16.0.4-302 / 16.5 → 16.5.0-780
· 벤더 권장 — “Cisco strongly recommends that customers migrate to Release 16.5.0-780.”
· 우회책은 없습니다 — “There are no workarounds that address this vulnerability.”
조치 적용 확인 ① 설치 버전 — 웹 UI Monitor > System Overview 또는 CLI version.
② 실행 버전 — CLI version(“Display AsyncOS version and build information”) 또는 API GET /api/v2.0/health/system_status의 version_details[].operating_system. 업그레이드 후 재부팅이 필수이므로 재부팅을 마친 뒤 확인한 값만 조치 완료 근거로 사용합니다.
③ 재부팅 — 필수. “you must reboot the email gateway after upgrading”(AsyncOS 15.5.5 릴리스 노트).
④ 클러스터 — 장비별로 개별 업그레이드합니다(clusterconfig disconnect → upgrade → resume, 전부 끝난 뒤 clusterconfig reconnect). 벤더: “A cluster must consist entirely of machines running the same version of AsyncOS.” 확인은 각 장비에서 CLI version.
침해 흔적 확인 아래는 모두 Cisco 권고 원문의 지시입니다.
· mail_logs에서 의심스러운 SQL 문을 확인합니다 — “To confirm any attempted exploitation of this vulnerability, review the mail_logs and look for suspicious SQL statements.”
· 클러스터면 각 장비의 로그를 확인합니다 — “If the device is part of a cluster, review the logs of each cluster device.”
· 벤더가 제시한 탐지 예시(벤더 표기: non-exhaustive):
  cisco-esa> grep -i "COPY.*TO PROGRAM" [IronPort Text Mail Logs Log name - Default: mail_logs]
· “The presence of any entry in the output may indicate malicious activity.”
· root 권한 획득 시 — “evidence of exploitation and indicators of compromise may be removed or hidden by the threat actors.”
· 외부 로그 교차 확인 — “Cisco strongly recommends that administrators cross-check the network logs and the firewall logs outside of the impacted device…”

침해가 의심될 때 벤더 권고(Recommendations 절)
· 물리 장비 — Cisco TAC에 문의하도록 권고합니다.
· 가상 장비 — 포렌식 데이터를 보존한 뒤 “Deploy a new virtual machine running one of the fixed software releases” · “Rebuild the product configuration” · 자격증명 갱신을 권고합니다.
· 클러스터 — “SSH key pairs are used for authentication purposes between cluster members. Upon successful exploitation of this vulnerability, private SSH keys used for this communication could be accessed on a compromised appliance.” 따라서 “Cisco strongly recommends restoring to a secure configuration each member of a cluster that contains at least one compromised appliance.”
· 복구가 불가능하면 — “If restoring the appliance is not possible, Cisco recommends contacting the Cisco TAC for further support.”
· Cisco Secure Email Cloud 사용 환경은 Cisco가 자체 위협 인텔리전스 조사를 수행했다고 밝혔습니다.

④ 영향 버전 표기가 출처마다 다릅니다. CVE 레코드의 구조화 필드(7.6.0~7.6.2 이하 등, 7.0·6.4 없음), 같은 레코드의 설명문(7.6.0 through 7.6.3 등, 7.0·6.4 포함), KISA #2539 표(7.6.0 이상 7.6.4 미만 등)가 서로 다릅니다. 어느 한쪽으로 단정하지 않고 세 값을 모두 기록했습니다. 실제 판단은 벤더 권고 원문 확인 후에 하십시오.
조치 지난 호 조치를 그대로 유지합니다 — FortiOS 7.0.18 / 7.2.12 / 7.4.9 / 7.6.4 이상, FortiSwitchManager 7.0.6 / 7.2.7 이상. FortiOS 6.4는 위 ③에 따라 상위 버전으로 이전. RUGGEDCOM APE1808은 Siemens 절차에 따라 Fortigate NGFW V7.4.9 이상.

침해 흔적 확인 벤더 원문 미확인으로 벤더 IoC는 [미확인]입니다. KEV 등재(9/9) 건이므로 패치와 별도로 패치 전 기간의 침해 흔적 점검은 계속 필요합니다 — 지난 호에 안내한 일반 점검 항목(모르는 관리자 계정, 설정 변경 이력, 낯선 VPN 세션·외부 연결)을 유지하십시오. 이는 벤더 IoC가 아닙니다.
