1. 한눈에 보기

지난주 보호나라에는 보안 업데이트 권고 4건이 게시되었습니다(MS 9월 정기, Adobe Commerce, PostgreSQL, Linux 커널). 이 중 Windows PC·서버 환경에 광범위하게 해당하는 것은 MS 9월 정기 업데이트이며, 실제 공격에 악용 중인 제로데이 2건이 포함되어 있어 이번 주 내 PC·서버 패치 적용이 필요합니다. PostgreSQL·Linux는 서버 운영 담당자, Adobe Commerce는 해당 솔루션 운영 시에만 확인하면 됩니다.

⚠ 긴급 추가(9/14 게시) — 집계 기간 이후 게시되었지만 위험도가 높아 함께 안내합니다. Fortinet FortiOS(CVE-2025-25249)는 CISA 악용 확인 목록(KEV)에 등재된 인증 불필요 원격코드실행이고, GitLab(CVE-2026-85706)은 CVSS 10.0 만점의 인증 없는 임의 파일 읽기입니다. 해당 장비·서버를 운영하는 환경에서는 즉시 확인 바랍니다.

2. 공지별 조치 방법과 조치 확인 방법
2-1. MS 9월 정기 보안 업데이트 [긴급 · 제로데이 2건 악용 확인]
무엇이 문제인가 9/8(현지) 발표된 정기 업데이트로, 13개 제품군(Windows 11·Server 2016~2025, Office, SharePoint, Exchange, SQL Server, .NET, Visual Studio, Dynamics 365, Azure)에 걸쳐 역대 최다인 약 960여 건의 취약점을 수정했습니다. 특히 아래 2건은 이미 실제 공격에 사용되고 있습니다.
· CVE-2026-81963 Windows Update Stack 권한상승(CVSS 7.8) — 링크 추적(link following) 결함으로 일반 사용자 권한에서 SYSTEM 권한 획득
· CVE-2026-85880 Windows ALPC 권한상승(CVSS 7.8) — 힙 오버플로로 SYSTEM 권한 획득
둘 다 "이미 들어온 공격자가 관리자 권한을 얻는" 유형이라 피싱 메일·악성 문서와 결합되면 PC 한 대 감염이 전체 장악으로 이어질 수 있습니다. 서버 담당자는 추가로 CVE-2026-69730 Windows DNS Server RCE(CVSS 9.8, 인증 불필요)와 CVE-2026-69676 Kerberos RCE(CVSS 8.8)를 우선 확인하세요.
조치 방법 ① Windows PC: Windows 업데이트(설정 → Windows Update → 업데이트 확인) 실행 후 재부팅까지 완료. 재부팅 전에는 패치가 적용되지 않습니다. Office도 파일 → 계정 → 업데이트 옵션 → 지금 업데이트 실행.
② Windows 서버: WSUS/SCCM 승인 후 배포. DNS 서버·도메인 컨트롤러(Kerberos)·Exchange·SharePoint는 우선 순위 1순위로 점검 창 확보.
③ Windows 10: 확장 보안 업데이트(ESU) 미등록 PC는 이번 패치를 받을 수 없으므로 Windows 11 전환 또는 ESU 등록 필요(KB5122878는 ESU 전용).
참고 KB: Windows 11 KB5124008 / KB5122880 (버전별 상이)
조치 확인 방법 · PC: winver 실행 → OS 빌드가 9월 누적 업데이트 빌드인지 확인. 또는 PowerShell에서 Get-HotFix | Sort-Object InstalledOn -Descending | Select -First 5로 9월 KB 설치 여부 확인.
· 설정 → Windows Update → 업데이트 기록에서 "2026-09 누적 업데이트 … 성공적으로 설치됨" 확인.
· 조직 단위: WSUS/Intune 준수 보고서에서 미적용 단말 목록 추출 → 담당자에게 개별 통보. 자산관리 시스템이 있다면 빌드 번호 기준으로 일괄 조회.
· 서버: 패치 후 Get-HotFix -Id KB번호로 확인하고, 취약점 스캐너(Nessus 등)로 재스캔하여 해당 CVE가 더 이상 검출되지 않는지 확인.
참고MSRC 업데이트 가이드 msrc.microsoft.com/update-guide/releaseNote/2026-Sep · KISA 공지 #2534
2-2. PostgreSQL 보안 업데이트 [높음 · CVSS 최대 8.8]
무엇이 문제인가 PostgreSQL 14~18 전 버전에 걸친 6건입니다. 서버 쪽과 클라이언트 쪽이 섞여 있다는 점이 중요합니다.
· CVE-2026-6473 (8.8) 서버 정수 오버플로로 메모리 할당 크기 오류 — 일반 DB 계정으로 접속만 가능하면 공격 가능
· CVE-2026-6637 (8.8) contrib 모듈 refint 스택 오버플로·SQL 인젝션
· CVE-2026-6479 (7.5) SSL/GSS 초기화 과정의 무한 재귀 → 인증 없이 서비스 거부(DoS) 가능
· CVE-2026-6475 (8.8) pg_basebackup/pg_rewind, CVE-2026-6477 (8.8) libpq — 악의적/침해된 서버가 접속하는 클라이언트 쪽 파일·메모리를 덮어씀
· CVE-2026-6476 (7.2) pg_createsubscriber SQL 인젝션 (17, 18만 해당)
조치 방법 ① DB 서버: 마이너 버전 업그레이드 — 14 → 14.23, 15 → 15.18, 16 → 16.14, 17 → 17.10, 18 → 18.4 이상. 마이너 업그레이드는 데이터 변환 없이 패키지 교체 + 재시작으로 끝납니다(apt/yum upgrade postgresql-XX 후 systemctl restart postgresql).
② 앱 서버·운영자 PC: libpq와 클라이언트 도구(psql, pg_dump, pg_basebackup)도 같은 버전으로 업데이트. 컨테이너 이미지라면 베이스 이미지 재빌드.
③ 즉시 패치가 어려운 경우 임시 조치: 5432 포트 접근을 앱 서버 IP로 제한(방화벽/pg_hba.conf), refint 확장 미사용 시 제거(DROP EXTENSION refint), 신뢰할 수 없는 서버로의 pg_basebackup/pg_rewind 실행 금지.
조치 확인 방법 · 서버: psql -c "SELECT version();" 또는 SHOW server_version; → 위 해결 버전 이상인지 확인. 재시작 전에는 구버전 프로세스가 계속 떠 있으므로 pg_postmaster_start_time()이 패치 시각 이후인지도 확인.
· 클라이언트: psql --version, pg_config --version, 앱 서버에서 ldd $(which psql) | grep libpq 후 해당 라이브러리 패키지 버전 확인(dpkg -l | grep libpq / rpm -q postgresqlXX-libs).
· refint 사용 여부: SELECT extname, extversion FROM pg_extension;
· 취약점 스캐너로 재스캔하여 CVE-2026-6473 등이 미검출인지 확인.
참고postgresql.org/support/security · KISA 공지 #2536
2-3. Linux 커널 보안 업데이트 [높음 · CVSS 7.8]
무엇이 문제인가 CVE-2026-31554: 커널 6.7에서 도입된 새 시스템콜 futex_requeue()가 원본·대상 futex의 플래그 불일치를 허용해 Use-After-Free가 발생합니다. 로컬 일반 계정에서 root 권한 획득이 가능한 유형이며, 컨테이너 탈출이나 웹셸 이후 권한상승 단계에서 쓰입니다. 원격 단독 공격은 불가하므로 "높음"이지 "긴급"은 아닙니다.
영향: 커널 6.7 이상 ~ 6.12.80 / 6.18.21 / 6.19.11 / 7.0 미만. 해결: 각 브랜치의 해당 버전 이상.
조치 방법 · 배포판 커널 패키지 업데이트: Ubuntu apt update && apt install linux-image-generic, RHEL/Rocky dnf update kernel, 이후 재부팅 필수(라이브패치 미사용 시).
· 커널 6.6 이하(RHEL 9, Ubuntu 22.04 기본 커널 등)는 취약 코드가 없어 해당 없음. Ubuntu 24.04 HWE 커널, Fedora, 최신 Debian, 자체 빌드 커널이 주 대상.
· 재부팅이 어려운 서버는 배포판 라이브패치(Ubuntu Livepatch, RHEL kpatch) 적용 여부 확인.
조치 확인 방법 · uname -r로 현재 동작 중인 커널 버전 확인 (패키지만 설치하고 재부팅 안 하면 구버전이 계속 실행됨).
· 배포판 커널은 버전 번호가 upstream과 다르므로 벤더 어드바이저리로 판단: RHEL rpm -q --changelog kernel | grep CVE-2026-31554, Ubuntu apt changelog linux-image-$(uname -r) | grep CVE-2026-31554 또는 Ubuntu CVE 트래커 조회.
· 자체 빌드 커널: 6.7 이상이면 수정 커밋(027145ace09f 등) 포함 여부 확인.
참고NVD CVE-2026-31554 · KISA 공지 #2537
2-4. Adobe Commerce / Magento 보안 업데이트 [긴급 · 인증 없는 RCE · 해당 시]
무엇이 문제인가 CVE-2026-75650: 템플릿 엔진 특수문자 미처리(템플릿 인젝션)로 인증 없이 원격 코드 실행이 가능합니다. Adobe가 정기 릴리스를 기다리지 않고 핫픽스(APSB26-146)로 긴급 배포한 건입니다. 영향: Adobe Commerce 2.4.4~2.4.9, Commerce B2B 1.3.3~1.5.3, Magento Open Source 2.4.4~2.4.9 (2026년 8월 릴리스 이전).
조치 방법 · Quality Patches Tool로 핫픽스 VULN-39341 적용: composer require magento/quality-patches → vendor/bin/magento-patches apply VULN-39341 → bin/magento setup:upgrade && bin/magento cache:flush
· 패치 후 암호화 키 교체(crypt key rotation) 및 관리자 비밀번호·API 토큰·결제 게이트웨이 자격증명 전면 교체를 Adobe가 권고합니다. 이미 침해되어 암호화 데이터가 유출됐을 가능성을 전제한 조치입니다.
조치 확인 방법 · vendor/bin/magento-patches -n status | grep "39341\|Status" → 상태가 Applied인지 확인.
· 관리자 페이지 하단 버전 표기 및 bin/magento --version으로 8월 이후 릴리스인지 확인.
· 웹서버 접근 로그에서 패치 전 기간의 비정상 템플릿 문법({{, }}) 포함 요청 여부를 점검해 침해 흔적 확인.
참고Adobe APSB26-146 · KISA 공지 #2535
2-5. [긴급 추가] Fortinet FortiOS / FortiSwitchManager [CVSS 9.8 · CISA KEV 등재]
무엇이 문제인가 CVE-2025-25249: 무선 컨트롤러 데몬(cw_acd)의 힙 오버플로. Security Fabric/CAPWAP 제어 트래픽을 받는 인터페이스에 조작된 패킷을 보내면 인증 없이 코드 실행이 가능합니다. 9/9 CISA 악용 확인 목록(KEV)에 등재되어 실제 공격이 확인된 상태입니다.
영향: FortiOS 6.4 전체, 7.0.0~7.0.17, 7.2.0~7.2.11, 7.4.0~7.4.8, 7.6.0~7.6.3 / FortiSwitchManager 7.0.0~7.0.5, 7.2.0~7.2.6
조치 방법 · 펌웨어 업그레이드: FortiOS 7.0.18 / 7.2.12 / 7.4.9 / 7.6.4 이상, FortiSwitchManager 7.0.6 / 7.2.7 이상. 6.4는 지원 종료로 상위 브랜치 마이그레이션 필요.
· 업그레이드 전 임시 조치: 외부 인터페이스 allowaccess에서 fabric 제거, 또는 local-in policy로 UDP 5246~5249(CAPWAP)를 신뢰 장비 IP만 허용.
· 이미 악용 중인 취약점이므로 패치와 함께 침해 여부 점검(비인가 관리자 계정, 설정 변경 이력, 알 수 없는 아웃바운드 연결)을 병행.
조치 확인 방법 · CLI get system status → Version이 해결 버전 이상인지 확인. HA 구성이면 양쪽 노드 모두 확인.
· show system interface로 외부 인터페이스의 allowaccess에 fabric이 없는지 확인.
· FortiGuard PSIRT 페이지(FG-IR-25-084)의 최신 영향 버전 표와 재대조. 외부에서 CAPWAP 포트 스캔으로 응답 여부 확인.
참고FortiGuard FG-IR-25-084 · KISA 공지 #2539
2-6. [긴급 추가] GitLab CE/EE [CVSS 10.0 · 인증 없는 임의 파일 읽기]
무엇이 문제인가 CVE-2026-85706: 저장소 commits API의 경로 제한·인증 누락으로 로그인 없이 GitLab 서버의 임의 파일(설정 파일, 시크릿, DB 접속 정보 등)을 읽을 수 있습니다. 같은 패치에 GraphQL 역직렬화 RCE(CVE-2026-87719, 긴급) 포함 총 18건이 수정되었습니다.
영향: 18.7 ~ 19.1.7, 19.2.0 ~ 19.2.5, 19.3.0 ~ 19.3.1
조치 방법 · 19.1.8 / 19.2.6 / 19.3.2 이상으로 즉시 업그레이드(Omnibus: apt/yum upgrade gitlab-ee, 자동 재구성됨).
· 인터넷에 노출된 GitLab이라면 업그레이드 전까지 방화벽/리버스프록시에서 /api/v4/projects/*/repository/commits 경로를 신뢰 가능한 내부 IP로 제한.
· 패치 후 gitlab-secrets.json, DB 비밀번호, 러너 등록 토큰, CI/CD 변수에 저장된 시크릿 교체 검토(파일 읽기가 이미 시도됐을 수 있음).
조치 확인 방법 · 관리자 영역 → 개요(/admin) 또는 gitlab-rake gitlab:env:info로 버전 확인. API로는 curl -H "PRIVATE-TOKEN: …" https://gitlab.내부/api/v4/version.
· nginx 접근 로그에서 패치 전 /repository/commits 요청 중 .., %2e%2e 등 경로 조작 문자열이 포함된 비인증(401 아닌 200) 요청이 있었는지 점검.
참고GitLab 19.3.2 패치 릴리스 · KISA 공지 #2538
